# 选题方向讨论（数值误差 → 行为差异）

---

## 零、背景

- 毕设题目：《张量计算的数值误差与行为差异分析》（见 `docs/选题说明-张量计算的数值误差与行为差异分析.pdf`）。
- 核心要求：以求和归约/点积/矩阵乘法为对象，比较 GPU 与昇腾 NPU 的数值误差与执行一致性；参考论文 5 篇（Mind the Gap、Taming Bitwise Behavior、Kernel Contracts、Testing GPU Numerics、FP Non-Associativity）。
- 时间线：11/20 跑通初步比较并选切入点，12/05 根据第一轮分析调整方向。
- 算力（见 `AGENTS.md` §4）：`npu` = Ascend 950PR ×3（CANN 9.1，ssh huawei-server-run）；`gpu` = Colab T4（colab-pi）；本机 RTX 4050 仅做小规模 sanity check，无 nvcc。

## 一、`docs/chats/Numerics.md` 这张表的定位

之前整理的 33 条浮点误差分类表，是面向 LLM RL 训练一致性问题（GRPO、vLLM/Megatron 训推不一致、MoE 路由漂移）建的，范围比本选题大很多。对这次毕设的可用性分三档：

- **核心可用**：第 1、3、4、6、7、8、9 条（表示误差/舍入/FMA/swamping/截断/SFU 近似）、第 10、11、13 条（归约树/tiling/指令重排，对应"归约顺序与并行分块"方向）、第 22 条（算子库版本差异）、第 26 条（灾难性抵消，对应"数值敏感输入"方向），以及"结合律失效""RN 一致只是必要条件"两句纠正。
- **背景可用**：第 17/18/20 条（低精度累加器/量化）帮助判断偏差是设计使然还是异常；横向属性 A/B/C（确定 vs 抖动、有界 vs 发散、连续 vs 离散）可直接作报告里的误差分类方法论。
- **基本无关，建议砍掉**：第 16、21、24、25、27 条（序列级重要性放大、训推条件分布不一致、GRPO clip 错层、MoE 路由）、第 31 条（硬件 SDC）——这些是训练一致性问题，混进本选题报告会显得跑题。

## 二、原始顾虑

用户提出两点担心：

1. "张量计算"听起来不够有水平，遇到的问题都偏老生常谈（表示误差、舍入、归约顺序这些都是教科书级内容）。
2. "GPU vs NPU 数值误差对比"本身已经有论文①做过系统性工作，缺乏独特切入点。

## 三、重新框定的方向

**问题不在领域，在故事落点**。把主线从"比较谁更准"换成两件更有独特性的事：

1. **刻画一颗几乎没有公开数值行为研究的新芯片**：950PR 是全新一代（CANN 9.1 新栈），参考论文①③测的都是 910B 或更早代际，这颗卡的数值行为指纹本身就是空白，不需要发明新方法，只需要把已有方法第一次用在它身上。
2. **从"数值误差多大"升级到"误差何时外溢成行为差异"**：呼应选题标题里"行为差异"四个字。大多数同类工作只报 ULP 级偏差，很少追问"这个偏差何时让 argmax/top-k 这类离散决策翻转"——这对应 `Numerics.md` 第 27 条"离散分支跳变"，是被低估的切入点。

## 四、具体实验设计：从数值误差到行为差异

**核心思路**：数值误差是连续量，单独报告很难判断"有没有问题"；一旦误差喂给一个离散决策点（argmax/top-k/符号判断/比较），误差就可能跨过决策边界，产生质变而非量变。要刻画的是：多大的数值误差、在什么条件下，会让 GPU 和 NPU 做出不同的离散决策。

### 4.1 选算子：接一个离散决策函数

单纯 `sum` 没有自然决策点，需要在 matmul/sum 之上接 B(·)：

- matmul + argmax（模拟最简分类头：`logits = x @ W`，`label = argmax(logits)`）——优先做这个，复用论文②③的 matmul 方法论，实现成本最低。
- 打分 + top-k（模拟 attention 选 token 或 MoE-gate 选专家，对应 `Numerics.md` 第 27 条）——Phase 2 再做。
- 比较/符号判断（`x > threshold`，对应 ReLU 边界）。

### 4.2 按"决策余量"（margin）构造输入，而非纯随机

关键变量是 top-1/top-2 候选之间的差距（margin），人工构造一组 logits，让 margin 从 `1e-1` 扫到 `1e-7`（逼近 FP32/FP16 噪声量级），主动把输入推进"容易翻转"的区域。

### 4.3 三方对照

对每个 margin 值，分别记录：

- FP64 CPU 参考的 argmax（ground truth）
- T4 上 FP32/FP16 的 argmax
- 950PR 上同精度的 argmax

分三类事件统计：GPU 偏离参考、NPU 偏离参考、GPU/NPU 互不一致——三类分开记，因为"两边都错但错得一样"和"两边互相矛盾"性质不同。

### 4.4 产出：翻转率 vs margin 曲线

不只报最大偏差，而是画出"margin 多大以下翻转概率显著上升"的曲线，比较不同精度配置（FP32/FP16/NPU 默认精度）曲线陡峭程度——这条曲线本身就是 950PR 的可复现数值指纹。

### 4.5 从合成扫描到真实数据

合成 margin 扫描证明"理论上会翻转"；更有分量的部分是统计真实 softmax 输出（小模型 logits 或公开数据集）的 margin 分布，叠加第 4.4 步的翻转阈值，回答"按真实分布估计，大约多少比例样本处于决策不稳定区间"。

## 五、排期

- **Phase 1（到 11/20）**：仅做 matmul+argmax 的合成 margin 扫描，GPU(T4) vs NPU(950PR) vs FP64 参考，产出翻转率曲线。自洽、工作量可控。
- **Phase 2（到 12/05）**：视 Phase 1 结果，扩展到 top-k/路由决策 + 真实数据分布分析；同时需要先在 `npu` 机器上花半天到一天探查 `torch_npu` 暴露了哪些归约/分块可控参数，决定"归约顺序与并行分块"这条线能做到多深（若 NPU 侧基本黑盒，则该方向降级为 GPU 内部机制分析 + NPU 作对照）。
