# 全部意见汇总（含 FMA 新讨论）

---

## 零、总纲：三句话

1. **论文层**：框架骨架值得发表，但被“定律”这个词和未证的 √R 绑架——降级或补证，二选一。
2. **概念层**：R 不是一件事，是 **R_struct（结构上界）+ R_eff（输入实际）+ ρ（修正因子）**；再往上统一成 **N_round（舍入事件计数）**，FMA 是它 N_round→1 的极限。
3. **工程层**：对昇腾编译器，价值不是新 pass，而是补上“精度结构”这个观测维度——让 lowering 阶段的结构分叉（tree-reduce 行分组差异、FMA contraction 差异）在测试失败之前被看见。

## 一、论文层面：审稿意见

### 1.1 总体判断

**Major Revision。** 问题重构（从“跨平台误差普查”到“可黑盒测量整数 → 误差映射”）正确且有价值；6 个候选淘汰到 1 个的“击杀列表”是全文最有信息量的部分；四条方法纪律诚实。但**标题写“顺序深度定律”，正文却自认“√R 指数未推导”“2.3e-3 是拟合值”“exact width 大概率测不出”**——主张与证据严重张力。

### 1.2 五个 Major

**M1（最致命）：“定律”的合法性**

- 链式 `A = 0.51R`：0.5 是平凡上界（每次舍入最多 ½ulp）；0.51 略大于 0.5 说明实测接近上界，但“为什么接近上界”需 worst-case 构造下的严格论证（对抗探针 + 单调同号吞并可做）。没有论证，0.51 就是拟合常数。
- 树式 `A ≈ 0.5√R`：作者自认“没推导出来”“随机游走差好几个数量级”。不能把自认推导失败的规律写进标题。
- **建议**：补两项推导（√R 推导检查是否差在归一化分母选错上：每层误差 ~ u·|partial sum|，|partial sum| ~ √(该层元素数)，求和应能给出 √R 形式的系数量级）；做不到就把“定律”降级为“经验标度律”，§2 标注每条律的推导状态（已证/部分证/经验）。

**M2：R 的定义循环与可操作性**

- R 定义依赖输入（“那一团”取决于数据分布），又被当作“对抗探针几百次 sum 测出的整数”预测随机输入——循环。
- 1.1~1.5 倍偏差恰是“对抗 R ≠ 随机 R”的体现，不是预测误差。
- “几百次 sum”“几秒测出”需给测量协议、误差棒、R(n) 稳定性（4050 随 n 阶跃到 60+ 说明 R 非纯结构常数）。
- **建议**：§3 增“R 操作定义与测量协议”；用第二节的 R_struct/R_eff 拆分直接消解循环。

**M3：四端落位的统计强度**

- 四端（Ascend 2–4、numpy 17、CPU 33、4050 35.6）是单次还是分布？需箱线图、测量次数、跨 torch/驱动版本稳定性。
- “昇腾各层树化 → 最准”有逻辑跳跃：若拓扑对幅度是二阶的（§四），为什么“各层树化”能推出“最准”？需拆开“结构原因”与“R 原因”。
- **建议**：补同后端多版本（至少两个 torch 版本）+ 同版本多输入类落位稳定性。

**M4：与论文 2 的区分是否成立**

- “论文 2 要位级等价所以要完整拓扑，我要幅度所以粗参数够”——动机成立，证据不足。全文无“论文 2 描述符 → 误差幅度”对照实验。
- 审稿人会问：论文 2 完整描述符是否也能预测同样误差（只是更贵）？若是，本文贡献是“更便宜的可迁移参数”而非“新定律”。
- **建议**：补 baseline——用论文 2 完整描述符在同批数据做误差预测，比较精度与成本。

**M5：负面结论需真正证明**

- “w·δ < 0.5ulp 与 δ ≈ u 不能同时满足 → 大概率不可黑盒测”——“大概率”让它成猜测。
- **建议**：要么给信息论下界（多项式次黑盒查询无法区分 w 与 w+1），要么降级为“未找到测量方法”（弱负面结论）。含糊负面结论不如不写。

### 1.3 六个 Minor

| 编号 | 问题 | 建议 |
|---|---|---|
| m1 | A = \|err\|/(u·Σ\|x\|) 口径要前移 | “抵消输入下 ulp 距离无意义”是度量设计的前提（ulp 爆到 10¹³ 才必须用 Σ\|x\| 归一化），提到 §1 开头作度量选择论证 |
| m2 | 交叉点（最坏 R≈3、典型 R≈33）只给数值 | 给推导与置信区间；交叉点是拟合常数的函数，常数误差会传播；1275√R 校准对常数误差的敏感度要说明 |
| m3 | 树常数 2.3e-3 是 strided 树拟合值 | 双标定（strided vs 连续折半）进正文 §2 必做，它是 numpy 与 CPU 区分度来源 |
| m4 | API 间差 8300 倍被归“装修” | 说明落位粒度是 API/flag 级而非硬件级；四端表要明确“测的是 ATen 还是 GPU” |
| m5 | 真实负载案例是“还缺” | 这是接收门槛，不是可选。至少一个小 transformer 的 softmax/layernorm 归约，给“预测 vs 实测”对照 |
| m6 | 四条纪律独立成节但只叙事 | 量化失败代价，如“第一版 ±L 探针让 4/4 后端误判为同链，修正后 3/4 反转” |

### 1.4 修改优先级

| 优先级 | 事项 |
|---|---|
| 必做 | M1（补证或降级）、M2（R 操作定义）、M5（负面结论证死或降级） |
| 强烈建议 | M3（落位稳定性）、m5（真实负载案例） |
| 建议 | M4（论文 2 baseline）、m1/m2/m3（口径前移、交叉点区间、树常数双标定） |

## 二、概念层面：R 与 N_round 的统一语言

### 2.1 三个 R 被混用

| 符号 | 含义 | 性质 |
|---|---|---|
| **R_struct** | 对抗探针测出的结构顺序深度 | 纯结构量，与数据无关，后端/flag 指纹 |
| **R_eff(x)** | 给定输入下实际发生的亚 ulp 吞并次数 | 输入×结构联合量，R_eff ≤ R_struct |
| **ρ(x) = R_eff/R_struct** | 输入类相关修正因子 | 1.1~1.5 倍偏差就是 ρ 的标定结果 |

**预测式改写**：`A(x) ≈ f(R_struct) · ρ(x)`。这一改，M2 的定义循环消失，“预测不准”变“ρ 标定”。

### 2.2 机制一句话

**R 是“亚 ulp 整块吞并事件”的计数**：累加器遇到比自己半个 ulp 还小的加数，把它整个丢掉（舍入回自身），误差就是被丢掉的东西之和。判据 `|addend| < ½·ulp(acc)`。

- **链**：兄弟加数永远远小于累加器 → 几乎每次吞并 → 吞并次数 ≈ 链长 L → 损失同号累积 → **A ∝ R，线性**。
- **树**：兄弟子树每层翻倍，两三层后超 ½ulp → 不再整块吞并，只剩每层 ≤½ulp 普通舍入、符号随机 → **A ∝ √(层数)，饱和**。

“拓扑二阶、深度一阶”不是巧合：**拓扑改变每层吞并多少，深度改变吞并发生多少次**；幅度主要由次数决定，次数由深度封顶。

### 2.3 R 不是什么

- 不是并行度（并行度高但 R 可小，如树化）
- 不是树深本身（树深只是链式 R 的上界、树式层数的载体）
- 不是精确宽度 w（w 是“一次舍入精确合并多少”，R 是“发生多少次吞并”）
- 不是纯输入量也不是纯硬件量——**是输入×结构的联合量，结构给上界，输入定实际值**

### 2.4 更高一层：N_round（舍入事件计数）——含 FMA

建议把语言统一成：

> **N_round**：一个表达式/归约序列内发生舍入的事件总数。
> - 归约链：N_round ≈ R_struct，误差 A ∝ N_round（线性律）
> - 归约树：N_round 被层数封顶，误差 A ∝ √N_round（饱和律）
> - **FMA：N_round = 1；乘+减：N_round = 2。这是 R 框架的 N_round→1 极限。**

这样 FMA 不是“另一个问题”，而是**框架的边界条件**。R_struct/R_eff/ρ 的拆分语言跨运算类复用：FMA 的结构上界是理论舍入次数（1 或 2），“实际可见差异”取决于输入是否暴露两次舍入差异——**ρ 因子就是“输入类是否暴露两次舍入差异”**。

## 三、编译器/软件工程层面：三个结合点 + 一个警告

### 3.1 结合点一：给归约重排序做“精度定价”

- LLVM `-ffast-math`（含 `reassoc`）、MLIR `fastmath<reassoc>` / `enableFpReductionReordering` 允许重排，但**编译器不知道重排后误差恶化多少**。
- `A ≈ 0.51R`（链）/ `A ≈ 0.5√R`（树）正是缺失的“精度价目表”：向量化把链变树，R 降，误差按 √ 律收缩；规避依赖链拉长顺序深度，R 升，误差按线性律恶化。
- CiRE 已对 LLVM IR 做 fast-math 后的舍入误差静态分析，**缺的正是“结构→幅度”闭式映射**。
- **做法**：把 R 作为归约 lowering 的精度代价特征，挂在 `vector.reduce` / `arith.addf` 的 `fastmath` 属性旁。

### 3.2 结合点二：R 作为可嵌入编译器的探针返回值

- 轻量 pass 跑在某 lowering 阶段后，回答“这次 pass 把归约顺序深度改成多少”。
- 与差分测试互补：差分测试只说“两个编译器输出不一样”；R 探针能说“哪个 pass、把什么结构参数改掉了”——**pass 粒度结构快照**（优化前 R=33，优化后 R=4，精度从链式区间跳进树式区间）。

### 3.3 结合点三：自动调优的精度侧标量特征

- PrecTuner、TAFFO 痛点：误差约束在搜索中怎么廉价评估（静态分析贵、采样慢）。
- R 是整数、几秒可测、已验证跨输入类预测误差（1.1–1.5 倍）→ **廉价代理特征**：先用 R 筛掉顺序深度会爆炸的配置，再精确验证少数候选。
- PrecTuner 用单参数 r 统一代码生成与调优，**R 是同一思路在误差侧的对应物**。

### 3.4 警告：粒度错位（与 m4 同源）

- API 间差 8300 倍说明 **R 落位粒度是 API/flag 级，不是硬件级**。
- 编译器关心“打开这个 flag 让 R 怎么变”，不是“这块 NPU 指纹是 4”。
- **测量协议要从“给后端测指纹”改为“给 pass 配置测 R 敏感度”**：固定硬件，扫 flag 组合，看 R 响应。这反而比四端落位更适合编译器场景。

### 3.5 最轻切入点

**MLIR `vector.reduce` lowering 路径插 R 探针 pass**，报告 fastmath 重排序前后的 R 变化，用两条律给误差上界位移估计。CiRE 证明 LLVM IR 层误差静态分析可行、有人做；你补的是它没有的**结构深度维度**。

## 四、昇腾 NPU 编译器层面：两个具体场景

### 4.1 场景一：tree-reduce 的 bit-exact 失败

- 生态已有案例：Triton `TreeReduceV2` 在 fp32 RA 下与 `torch.sum` golden 只有约 1/3 输出列 bit-exact，近抵消输入下 **1034 列必现越过 `atol=1e-4`**。
- 根因：两者第一轮**行分组方式不同**——Triton 用 stride/mod 交错读 16 行，CANN 内置 ReduceSum 折叠 16 个**连续行**；跨对蝶形树完全一致，唯独这层分组不同。
- 这是纯 R_struct 问题：**蝶形树没变，但“谁先和谁加”变了，R_struct 在这层分叉**。
- R 探针能在**不跑完整测试**下回答：“这次 TreeReduceV2 的 lowering 把第一轮 R_struct 改成多少？和 CANN 内置路径差在哪一层？”——比用 1436 个测试用例反向定位快一个数量级。

### 4.2 场景二：FMA 的 IR 不可区分精度问题

**问题描述**：FMA 的 IR 和“减法 + 比较”的 IR 长得一模一样，静态区分不开。FMA 是一次舍入，另者是两次舍入，精度不同但 IR 无法区分。

**在框架里的位置**：这是 R 框架的 **N_round→1 极限**情形。FMA：N_round=1；乘+减：N_round=2。链式律 `A ∝ R` 在 R=1、R=2 时退化为“一次舍入 vs 两次舍入”的经典分析——**同一个量的不同取值域，不是硬套**。

**它验证了框架的核心方法论跨运算类成立**：
- 构造 `a*b` 的精确积低 p 位非零（需 2p 位表示），选 `c` 使“一次舍入”和“两次舍入”输出恰好差 1 ulp；
- 一次调用，输出只能是 A 或 B，**零噪声一个确定比特**——与归约探针 (+1, −1, 2⁻²⁵) 设计同构；
- **“结构在 IR 不可见，但对抗探针能读出”**——这是 R 框架方法论的 FMA 版本。若在归约上成立、在 FMA 上也成立，“可迁移”就不只是跨后端，而是**跨运算类**。对 M4（与论文 2 区分）和 m5（真实负载闭环）都是加分项。

**它也暴露了框架的缺口**：你现在只有 R（吞并次数），没有单操作舍入次数符号——**需把 N_round 写进论文统一语言**（见 2.4）。

**对昇腾编译器的直接价值**：FMA contraction（`-ffp-contract` 那类决策）状态和“精度定价缺失”一模一样——**编译器知道可以合并，但不知道合并改变了多少舍入次数、误差上界位移多少**。R 框架能做：
1. **lowering 后插探针**：IR 区分不开，探针能。对给定 lowering 配置读出实际 N_round 是 1 还是 2。
2. **N_round 作为 contraction 决策的精度代价**：合并 FMA 把 N_round 从 2 降到 1，误差上界位移可估；反向，某些规避 FMA 的 lowering 把 N_round 从 1 抬到 2，是精度回退，应被 flag 出来。
3. **与 tree-reduce 共用同一探针框架**：归约探针测 R_struct，FMA 探针测 N_round——**同一个“结构不可见但可测”观测层**，只是量不同。

**警告：别把 FMA 硬塞进论文主线**。它对论文的帮助是**验证与边界**，不是新主线。若写成“框架还能处理 FMA”，审稿人会问“定律在 N_round=1 时预测精度如何”——需一个小实验回答：用 FMA 探针测 N_round，预测一次/两次舍入的误差差异，与实测对上。**做得出，加分项；做不出，又一个被标题绑架的主张**。建议放“框架边界与跨运算类验证”小节，一两页，一个对照实验，足矣。

### 4.3 R 探针在昇腾栈上的落点（由轻到重）

| 层级 | 做法 |
|---|---|
| **最轻** | Triton-Ascend lowering 之后、CANN 算子调用之前插探针。已有 `TreeReduceV2` 与 `AscendC::ReduceSum` 两条路径可对照。对给定 shape + tiling，用对抗输入（大数+极小量+反号）读 R_struct。不替代现有测试，只在 bit-exact 失败前给“哪层结构分叉”线索。 |
| **中等** | R_struct 作为 **tiling 选择附加约束**：`DichotomyReduceSum` vs 顺序累加之间，除 UB 开销和 R ≤ VL 约束外，加“预估 R_struct ≤ 阈值”精度护栏。比“一律升 FP32”更精细，比“不通过就回退”更有预测性。 |
| **中等（FMA）** | FMA 探针接入 contraction 决策：lowering 配置确定后，探针读出实际 N_round，作为精度代价标签挂在决策旁。 |
| **较重** | pass 粒度结构快照（3.2）+ 自动调优代理特征（3.3）+ MLIR `vector.reduce` 探针 pass（3.5）。 |

### 4.4 一句话总结昇腾部分

**R 框架给昇腾编译器提供的不是新优化 pass，而是一个目前完全没有的“精度结构”观测维度**：R_struct 让 pass 知道“我改了什么”，R_eff/R_struct 让编译器知道“这类输入会不会踩线”，N_round 让 contraction 决策知道“合并省了几次舍入”。tree-reduce 的 bit-exact 问题和 FMA 的 IR 不可区分问题已证明该维度缺失的代价——**探针至少能让下一次同类问题在 lowering 阶段被指出**，而不是在 1436 个用例里反向定位。

## 五、整合行动路线图

### 阶段一：概念清算（1 周，解 M2 + 统一语言）

1. 把 R 拆成 **R_struct / R_eff(x) / ρ(x)**，写进定义。
2. 预测式改为 `A(x) ≈ f(R_struct)·ρ(x)`，1.1~1.5 倍从“预测误差”重述为“ρ 标定”。
3. 引入 **N_round** 作为统一语言，FMA 定位为 N_round→1 极限。
4. 论文 §3 补“R 操作定义与测量协议”（重复性误差棒、R(n) 曲线）。

### 阶段二：论文补证或降级（2–4 周，解 M1 + M5）

1. 补链式 0.51 的 worst-case 严格论证（对抗探针 + 单调同号吞并）。
2. 补树式 √R 推导（检查归一化分母是否选错），哪怕系数差 2 倍也写出来讨论差异来源。
3. exact width 负面结论：给形式化 SNR/信息论下界，或降级为“未找到方法”。
4. 做不到 1、2 → 标题“定律”改“标度律”，§2 标注推导状态。

### 阶段三：统计加固（与阶段二并行，解 M3 + m3 + m4）

1. 四端落位补多版本、多输入类、箱线图。
2. 树常数双标定（strided vs 连续折半）进正文。
3. 明确落位粒度是 API/flag 级。
4. 拆开“昇腾最准”的因果链（结构原因 vs R 原因）。

### 阶段四：闭环验证（接收门槛，解 m5 + M4 + FMA 边界）

1. 一个真实负载案例（小 transformer 的 softmax 或 layernorm 归约）：预测误差 vs 实测误差。
2. 论文 2 完整描述符的误差预测 baseline（精度 vs 成本对照）。
3. **FMA 对照实验**：探针测 N_round，预测一次/两次舍入误差差异，与实测对上——放“框架边界与跨运算类验证”小节，一两页。

### 阶段五：编译器落地（与论文并行，昇腾实际收益）

1. **最轻**：Triton-Ascend lowering 后插 R 探针，对照 `TreeReduceV2` 与 `ReduceSum` 两条路径。
2. **中等**：tiling 阶段加“预估 R_struct ≤ 阈值”精度护栏；FMA 探针接入 contraction 决策。
3. **较重**：MLIR `vector.reduce` lowering 插 R 探针 pass（对外可发表、对内可复用的交叉点）。

## 六、最需要记住的四句话

1. **论文层**：骨架值一篇好论文，但被“定律”这个词和 √R 这个未证指数绑架——**降级或补证，二选一**。
2. **概念层**：R 不是一件事，是 **R_struct（结构上界）+ R_eff（输入实际）+ ρ（修正因子）**；往上统一成 **N_round（舍入事件计数）**，FMA 是 N_round→1 的极限。拆开之后，定义循环、“预测不准”、FMA 归类三个问题同时消失。
3. **FMA 层**：它不是“又一个精度 bug”，是 **R 框架在 N_round→1 的边界测试**——验证“IR 不可见但黑盒可测”跨运算类成立，同时逼你把 N_round 写进统一语言。对昇腾，它给你一个与归约探针同构的 FMA 探针，把 contraction 决策也纳入“精度定价”。
4. **工程层**：对昇腾编译器，R 的价值不是新 pass，而是**补上“精度结构”这个观测维度**——让 lowering 阶段的 R_struct 分叉（tree-reduce 行分组差异、FMA contraction 差异）在测试失败之前被看见。
