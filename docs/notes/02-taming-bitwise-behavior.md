## 一句话

把 GPU 上「为什么两次确定性实现仍差最后一个 bit」拆成可命名、可复现、可静态检查的**归约顺序形式化参数（GEMMDesc）**；通过**极端数值相消探针**黑盒还原了 cuBLAS 的算术（在 Blackwell/Hopper 上 100% 逐位复刻，并反向抓出 cuBLAS 丢尾数的官方 Bug）；在 Triton 编译器后端强制实施平衡树归约并通过布局优化把性能救回甚至反超。

---

## 核心机理：归约树（Dependence Tree）与决定因素

- **数学本质**：浮点加法不满足结合律 $(a \oplus b) \oplus c \neq a \oplus (b \oplus c)$。GPU 归约本质是一个由 $\oplus$ 节点构成的依赖树，树的拓扑结构唯一决定二进制位结果。
- **三层归约体系**：$T = T_{\text{smem}} \circ T_{\text{warp}} \circ T_{\text{reg}}$（线程寄存器折叠 $\to$ Warp 内 Shuffle 交换 $\to$ 跨 Warp 共享内存折叠）。

### 决定位级结果的参数（GEMMDesc 描述符，最值得借鉴的形式化）：
| 因素 | 作用与机制 | 属于速度旋钮还是算术？ |
| :--- | :--- | :--- |
| `instruction_k` | 矩阵指令硬件折叠的乘积数（指令内部乘积**完全无顺序，共享单次舍入**） | **算术核心**（真正决定指令链长） |
| `use_fast_accum` | 乘积进入累加器是同一步舍入，还是先舍入乘积再舍入累加（一步 vs 两步舍入） | **算术核心** |
| `k_loop_step` | K 轴循环步长；无法整除的余数轮先跑还是后跑，会改变所有后续部分和 | **算术核心** |
| `span` & `k_cuts` | Split-K 切分段长及段内再切分（chained chunks），每次切开都关闭累加器**从 0 开始** | **算术核心** |
| `partial_dtype` / `merge_dtype` | Split-K 各分片保存的类型与二次合并相加的精度（FP32 还是输出类型） | **算术核心** |
| `layout` (GEMV) | 线程与数据索引的映射（连续切片 vs 跨步循环），直接改变树节点的物理归属 | **算术核心** |
| **`BLOCK_M` / `BLOCK_N`** | 仅决定哪个线程拥有哪个输出元素，每个元素各有独立累加器 | 纯速度旋钮（**不影响数值**） |
| **`BLOCK_K`** | 仅决定主循环单圈发射几条指令，累加器跨圈传递 | 纯速度旋钮（**不影响数值**） |
| **`num_stages` / Warp 特化** | 软件流水与异步加载只改变数据到达物理时间，累加链不变 | 纯速度旋钮（**不影响数值**） |

> **关键反直觉结论**：决定矩阵乘数值比特的是硬件单条指令的 `instruction_k`，**而不是软件分块的 `BLOCK_K`**！

## 硬件与张量核心语义假设

- **FP16 / BF16 / TF32**：一条矩阵指令把 `instruction_k` 个乘积在内部做**精确无损求和**，再与累加器做**一次舍入**：
  $$\text{acc} \leftarrow \text{acc} \oplus_{\text{fp32}} \left(\sum_{j < \text{instruction\_k}}^{\text{exact}} a_j b_j\right)$$
  因此**指令内部乘积没有顺序**，存活下来的规约顺序只有**跨指令的 $\oplus_{\text{fp32}}$ 链条**。
- **FP8 异常**：在 GB300 上，`mma.sync` 与 `tcgen05.mma` 在 FP16/BF16 逐位等价，但在 FP8 下**不逐位等价**。原因在于 FP8 乘加是以降低精度运行的，中间提升至更高精度的节奏（Promotion Cadence）在不同指令降级中不一致。

## 四项核心工作与量化结果

### 1. 黑盒逆向重建 cuBLAS（§4）
- **仪器一（运行时剖析）**：抓内核启动数、网格大小、是否申请 Workspace（区分单趟 vs Split-K）。
- **仪器二（数值探针，核心绝招）**：在全零轴上放置极端相消对 $+L=1024, -L=-1024$ 与极小数 $r=2^{-15}$。沿着 $K$ 轴移动该对。当大数与 $r$ 落在同一切块内，$r$ 被大数吞掉（输出 0）；一旦跨过切块边界，大数在后续块自行相消，$r$ 完好幸存。以此逆向探测出 cuBLAS 的边界表（Arch Profile）。
- **战果**：
  - 在 GB300/GB200/H100 上，在 110,813 个随机 FP16 形状上实现了 **100% 逐比特一致**。
  - **意外收获（附录 D）**：抓出 cuBLAS 在 nvjet Split-K 路径下的隐蔽 Bug（当满足 ALGO_ID=66 且 $K$ 无法整除切分时，会**漏算末尾丢掉 8 个数**，如 $K=8648$ 输出 8640）。

### 2. Triton 编译器后端强制平衡树与布局优化（§5）
- 在 Triton 后端把默认的向下递减 shuffle 改为向上递增计数（1, 2, 4, 8...），使得相邻 lane 优先配对，强制实施平衡树规约。
- **打破 20% 性能税**：因为树拓扑在逻辑上被固定锁死了，寄存器和共享内存的**物理数据布局（Data Layout）变成了一个自由的优化旋钮**！通过消除跨 Warp 同步开销：
  - GB300 和 H100 上的 27 个算子中有 19 个进入自由顺序性能的 10% 以内；
  - **H100 上的 10 个算子中有 6 个性能反超自由模式**（列求和最高反超 42%）；
  - 融合算子（GEMM + Epilogue）相比 cuBLAS + 独立内核基线快了 **95%~168%**。

### 3. PTX / AMDGCN 静态等价性检查器（§6）
- 无需执行，纯静态符号化遍历汇编。把指令还原为符号地址与规约依赖树，通过子节点规范化排序与自底向上签名哈希（Hash Signature）判定等价。
- 在 GB300 上认证了 51,152 个配置，GFX942 上认证了 4,500 个配置，**Soundness（可靠性）达到 100%（即断定为等价的在硬件上实测 0 误差）**。

### 4. 自动调优器（Autotuner）静态剪枝
- 把静态检查器作为 Triton Autotuner 的剪枝谓词，让调优器只在 **同一个位等价类(Bitwise-equivalence class)** 内搜索最快配置，兼得高性能与 100% 复现性。

## 可复用到本课题（GPU vs 昇腾 NPU 对比）的实操做法

1. **借用数值探针逆向昇腾黑盒**：
   - 昇腾 CANN 的矩阵切块也是黑盒。完全可以用同样的思路：在 Python 中构造行向量 $[r, L, -L, 0 \dots]$ 与全 1 矩阵相乘，移动相消对的位置，**反推出昇腾 Cube 核心的切分边界与 $instruction\_k$ 粒度**。
2. **警惕低精度（FP8/BF16）的“提升节奏”**：
   - 论文提到 FP8 在不同硬件指令间难以对齐，印证了在昇腾上做 FP8/BF16 时，中间累加器提升至 FP32 的时机（Promotion）是造成跨平台差异的主因。
3. **把全 1 矩阵（All-ones GEMM）作为残余边界测试的黄金探针**：
   - 针对非 16/32/64 对齐的 $K$（如 $K=8648$），输入全 1，数学真实结果必等于 $K$。这是检查昇腾底层在多核 Split-K 时是否发生“丢尾巴缺陷”的绝佳轻量级用例。
4. **区别“速度旋钮”与“数值旋钮”**：
   - 在比对两端配置时，不要把精力放在 `BLOCK_M/N` 上（它们不改精度），重点抓：两端切分 $K$ 轴的分段数、循环步长、以及部分和是以 FP32 还是目标精度写回。

## 疑问

- [x] **§4 黑盒重建的具体流程**：
  不是盲目枚举，而是“两步走”：先 Profiling 确定启动的 Grid 和工作区（缩小到算法族），再用 $+L, -L, r$ 探针沿轴探测切分边界；最后枚举有限的 Cost Model 决策点建立索引表（Arch Profile）。
- [x] **§5 平衡树 lowering 改动量**：
  改动非常聚焦，核心在后端降低为 shuffle 指令时反转步长循环方向（见论文图 3），由向后变为向前配对；更关键的收益是配合编写的 Data-Layout Optimization Pass。
- [x] **§6 汇编与 SASS 之间的 gap**：
  检查器只做到 PTX/AMDGCN 文本汇编级。作者承认 `ptxas` 汇编到 SASS 时理论上仍可能做激进重排，但实测 51,152 个配置无一出现假阳性，工程上可靠性极高。
- [x] **FP8 结论的警示**：
  在异构芯片对比中，FP8 几乎无法做到 Bitwise 等价（硬件在乘加阵列里的截断机制各异），因此跨平台（GPU vs NPU）对比应以 **FP16 / BF16** 作为位级对齐的主战场，FP8 重点分析其误差分布与溢出行为。
