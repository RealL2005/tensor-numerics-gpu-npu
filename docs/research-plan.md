## 0.1 一句话定位

**把"跨平台数值差异"这个不可迁移的普查式陈述，改造成"一个秒级可黑盒测出的整数 → 误差"的映射，
并明确这个映射的适用边界。**

- 量：`A = |err| / (u·Σ|x|)`（放大因子，u = 2⁻²⁴）
- 参数：`R_struct(n, impl, flag)` = 结构顺序深度（亚 ulp 整块吞并的次数）
- 律：链 `A_max = (δ/u)·R ≤ R`；树 `A_max = O(1)`；典型 `A_typ = max(0.51R/n, A_tree)`
- **边界（实测）**：只在**抵消/亚 ulp 族**成立；同号真实负载（softmax 分母、LayerNorm 方差、embedding 求和）
  三端 A 均在 ±1 内且无法排序

## 0.5 路线调整（重要）

"让真实训练崩掉"这条闭环不现实（需要长跑或恰好撞上病态 workload，成功也只是 1 bit）。
改为 **R1：把后果换成"逐比特复现"** —— 用黑盒探针拟合出某设备的归约顺序模型，要求输出**一位不差**。
判据二元、秒级、无法辩解；且直接对应选题说明"比较执行结果一致性"。

**已有结果**（报告 §11.22）：昇腾 950PR 的 fp32 `sum` 在 **n ≤ 8192** 上被 4 行零参数模型逐比特复现
（4 个 n × 3 族输入 × 80 次 = 全中）；n ≥ 12288 的第二层尚未定位（明确负结果）。

## 2. 五阶段路线（含状态）

### 阶段一：概念清算 ✅
- R 拆成 **R_struct / R_eff(x) / ρ(x)**，预测式写成 `A(x) ≈ f(R_struct)·ρ(x)`（定义循环消失）。
- 引入 **N_round**（舍入事件计数）作统一语言；**FMA = N_round→1 的极限**（未做实验，仅语言统一）。

### 阶段二：补证或降级 ✅（部分）
- 链律从"拟合 0.51"改为**推导** `(δ/u)·R ≤ R`。
- `√R` **撤回**，改为两项律并给出推导与膝点 `R ≈ 2.45√(n·log₂n)`。
- `w` 的负面结论降级为 SNR 上界。
- ⬜ 树项常数仍需更严格推导（现为量级正确、常数差 2–4 倍）。

### 阶段三：统计加固 ⚠️（部分）
- ✅ R_struct 带误差棒；线程数依赖已测；树常数双标定（strided 2.94e-3 / 连续 2.33e-3，A_max 均 −1.90）。
- ⬜ 多 torch / CANN 版本稳定性；⬜ 落位箱线图（多次重复而非单次）。

### 阶段四：闭环验证 ⚠️（关键一步失败，但已入正文）
- ✅ 真实负载三类归约（softmax 分母 / LayerNorm 方差 / embedding 求和）：**A 全在 ±1 内且 R 排序失败** →
  适用范围收紧（这是本轮最重要的负面结果）。
- ✅ 与论文 [2] 的精度-成本对照：完整描述符可逐位预测（我的模型 45/45），R 只需几十次调用但只有 2 倍以内精度。
- ⬜ FMA 边界实验（N_round = 1 vs 2 的对抗探针）：可做，但按评审"别硬塞进主线"，只作边界小节。

### 阶段五：编译器落地 —— **并且测量对象要改**（评审 §3.4 的重构意见）

评审指出的最重要一条重构意见，我原来漏了：

> **粒度错位**：API 之间差 8300 倍，说明 R 的落位粒度是 **API / flag 级，不是硬件级**。
> 所以测量协议应从"给后端测指纹"改为 **"给 pass / flag 配置测 R 敏感度"**：
> 固定硬件，扫 flag 组合，看 R 怎么响应。

这反而比"四端落位"更适合编译器场景——编译器关心的是"打开这个 flag 让 R 怎么变"，不是"这块 NPU 的指纹是几"。
`e38`（§11.16）已经证明这条路可行且因果清晰：**同一块卡、一个 Triton 文件、只改 BLOCK，
A 就从 0.93 变到 34336，链律预测命中 1.00**。这就是"精度定价表"的最小可运行版本。

三个结合点（评审给的，按落点由轻到重）：
评审给出与昇腾编译器的三个结合点（按落点由轻到重）：

1. **最轻（已有最小样例，`report §11.17`）**：Triton-Ascend 侧 `e39_triton_ascend.py` 已能在卡 2 上跑通，
   实测 CANN `torch.sum` A=0.20 而 Triton 改写最多 135（600 倍）。下一步即"对照 `TreeReduceV2` 与 `CANN ReduceSum` 两条路径
   （已知案例：两者蝶形树一致、仅第一轮行分组不同 → 约 1/3 列非 bit-exact，近抵消输入下越过 atol）。
2. **中等**：tiling 阶段加"预估 R_struct ≤ 阈值"精度护栏；FMA contraction 决策旁挂 N_round 标签。
3. **较重**：MLIR `vector.reduce` lowering 插 R 探针 pass（对外可发表、对内可复用）。

**已完成（只读）**：`--tree-reduce-v2` 有 ≥3 种结构 lowering、无精度判据、有 `dimR≤64` 阈值（报告 §11.18）。
**已完成（已改动并构建）**：分支 `feat/precision-pricing` / commit `241e7e884` 加了 `emit-precision-report`，
把 `A_max(chain)≤dimR` vs `A_max(tree)≤log2(dimR)` 与价差直接打在 lowering 阶段（报告 §11.20；
默认策略在 dimR=128 上比树贵 18.3 倍）。开关不改 IR，6/6 lit 通过。
**下一步**：让该诊断**参与选路**（`R_struct ≤ 阈值` 作为约束），那会改变 lowering 行为，需单独立项评估；
并可用 `e39` 的写法在昇腾上按 flag 组合实测 A，验证价目表的数值。

## 3. 下一步（按性价比排序）

0. **（新主攻）补齐 n ≥ 12288 的第二层**：已用探针定位到"块局部"（n=16384 时抵消只发生在 ~320 元素的子树内，
报告 §11.22），并用 ~30 个参数化模型排除了"连续分块再合并"这一族。
   → 下一步必须换成 **tree 重建**：以 (p,q,s) 判定器（答案只有 0/r，零噪声）对**单条 lane 的 256 个元素**
   恢复合并顺序（约 2–5k 次探针，卡 2 可承受），得到真实的局部树后再合成全局模型。
   达成后即可把逐比特区间推到 2²⁰，这是本课题最硬的可交付结果。
1. **补同号分支的律**（次攻）：softmax 分母/归一化这类"部分和单调增长"的输入，误差应满足
   另一种尺度关系（猜测 `A ~ √R`，因为部分和本身随 j 增长使 ulp(acc) 同比例放大，误差相互抵消）。
   这是一个纯模型即可做的推导+验证，不需要新硬件。
2. **ρ(x) 标定曲线**：以"加数同质度"或"部分和与分量之比"为横轴，测 ρ，做成一条可查的曲线。
3. **多版本稳定性**：同一份 sha256 输入在 torch 2.14/2.15（已有 T4/4050 两个版本）与另一 CANN 版本上各测一次 R_struct。
4. **FMA / N_round 边界**：已用现有 1 ulp 判别器收口（报告 §11.14，五端 API × FMA 表），
   并可写成 `N_round` 语言下的"框架边界"小节。
5. **把 `e38` 扩成一张"价目表"**：固定 4050，扫 Triton 的 BLOCK / num_warps / 是否 FMA，
   记录每个配置的 `R_struct` 与实测 A，做成"编译选项 → 精度代价"的对照表（这是评审 §3.1 要的东西）。
