# 选题细化：研究计划

> 来源：`张量计算的数值误差与行为差异分析.pdf`（选题说明）＋ 5 篇参考文献。
> 本文件是**可迭代**的：每轮实验后回填结论与调整。

## 1. 问题定义

对同一个数学上定义明确的张量计算 `f(x)`，在两个异构后端 `A = GPU`、`B = 昇腾 NPU` 上：

```
           x  ──►  f_A(x)  ──►  y_A
           x  ──►  f_B(x)  ──►  y_B
           x  ──►  f_ref(x) ──►  y_ref   （高精度：FP64 / 精确求和 / 更高精度库）
```

需要同时回答两个**不能混为一谈**的问题：

1. **一致性**：`y_A` 与 `y_B` 是否逐位相同？差多少？
2. **正确性**：`y_A`、`y_B` 各自相对 `y_ref` 的误差有多大？

仅比较 (1) 会出现「两端都错得一样」的假象；仅比较 (2) 会漏掉「两端误差都合格但结果不一致」的工程问题
（正是 batch invariance / 确定性训练关心的场景）。

## 2. 算子范围（先窄后宽）

| 优先级 | 算子 | 观察点 |
| --- | --- | --- |
| P0 | 一维求和归约 `sum` | 归约顺序、分块、累加精度、原子累加 |
| P0 | 点积 `dot` | 累加器精度、FMA 融合、是否走 Tensor Core |
| P1 | 矩阵乘 `matmul` | tile/split-K 形状、Tensor Core 输入输出精度、epilogue |
| P2 | 分块求和（手动 chunk） | 人为控制归约树形状，作为「实现变体」对照组 |
| P2 | 归约类算子（mean / max / softmax 分母） | 复合误差传播 |

入门实验建议只用**一维数组**，规模从小（1e3）到大（1e8），这样每一步误差都能解释；
`matmul` 需要同时扫 `(M, N, K)` 与 tile 配置，成本更高，放在 M2 之后。

## 3. 输入分布（敏感性维度）

| 名称 | 构造方式 | 预期暴露的问题 |
| --- | --- | --- |
| `uniform` | `U(-1, 1)` 或 `N(0,1)` 随机 | 基线 |
| `cancellation` | 成对 `±x` 交替 / 正负两部分各自求和再相减 | 灾难性抵消，误差相对值爆炸 |
| `mixed_magnitude` | 指数分布跨若干数量级（如 `1e-8 ~ 1e8`） | 大数吃小数，归约顺序高度敏感 |
| `large_offset` | `1e7 + ε` 型（小量叠加在大基数上） | 有效位丢失 |
| `denormal_extreme` | 含次正规数 / 接近溢出 | 硬件对异常值的处理差异（对照论文 4 的 NaN/Inf 分类） |
| `structured` | 全正 / 全负 / 单调递增 | 与随机输入对比，判断「顺序敏感」是否是主因 |

每个输入固定种子并**落盘保存**，保证两端使用同一份实际输入（选题说明中的明确要求）。

## 4. 精度与配置维度

- 数据类型：`fp32 / fp16 / bf16`（NPU 侧按实际支持情况）
- 累加类型：`fp32 累加` vs `fp64 累加` vs 默认
- PyTorch 开关：`torch.backends.cuda.matmul.allow_tf32`、`torch.use_deterministic_algorithms(True)`、
  `CUBLAS_WORKSPACE_CONFIG`、昇腾侧的确定性相关环境变量
- 图模式：eager vs `torch.compile`（论文 1 指出编译模式可能带来额外偏差）

## 5. 评价指标

设 `y` 为被考察输出，`r` 为高精度参考，`u` 为最后一个有效位的单位（ULP）。

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| `max_abs` | `max|y - r|` | 绝对误差 |
| `max_rel` | `max(|y - r| / (|r| + tiny))` | 相对误差（注意 `r≈0` 时失真，需单独报告） |
| `ulp_dist` | 逐元素位模式差值 | 位级误差，最适合与论文 2 的位级等价分析对接 |
| `bitwise_equal` | `y_A.view(uint) == y_B.view(uint)` 全等比例 | 跨平台一致性 |
| `atol/rtol 判定` | `|y_A - y_B| <= atol + rtol*|y_B|` | 与 PyTorch 测试套件口径一致（论文 1：`atol=5e-4, rtol=1e-4`） |
| `run-to-run` | 同一设备重复 N 次的波动（论文 5 的 `V_s / V_ermv / V_c`） | 区分「跨平台差异」与「同平台不确定性」 |

> 报告时必须注明：比较的是哪一个指标、参考怎么算、容差取多少、统计的是 max 还是均值。

## 6. 实验矩阵（第一轮）

```
算子(P0: sum, dot) × 输入分布(6) × 规模(1e3,1e4,1e5,1e6,1e7) × 精度(fp32, fp64) × 设备(cpu, gpu, npu) × 重复(≥5)
```

总计约 2 × 6 × 5 × 2 × 3 × 5 = 1800 次运行，量级可控。先跑 `sum`，再补 `dot`。

## 7. 差异归因方法（从论文 4、2 借用）

1. 从**最小可复现片段**开始（几十行内、单算子、固定输入）。
2. **单因素变换**：一次只改一个维度（规模 / 分布 / 精度 / 分块 / tile），看差异是消失、不变还是放大。
3. **缩减（delta debugging）**：逐步删元素/缩规模，保留仍能触发差异的最小子集。
4. **中间量对比**：分块部分和、累加器内容逐级比对，定位误差注入点。
5. **反事实检查**：把两端的归约顺序人为统一（如都强制顺序累加），若差异消失 ⇒ 顺序是主因。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 昇腾侧 PyTorch 算子/精度支持不全（论文 1：910B 少 17.5% 硬件加速算子，部分算子静默降精度） | 先做能力探测脚本；对不支持的组合显式记录「不支持」而非静默跳过 |
| 两端环境难以对齐（驱动、算子库版本） | 记录版本清单（`npu-smi info`、`nvidia-smi`、torch/ CANN 版本）随结果归档 |
| 高精度参考不可得 | 求和用精确算法（`math.fsum` / Kahan / 有理数），点积与矩阵乘用 FP64 或 `mpmath` |
| 观察到的差异只是「同一平台随机性」 | 每配置重复 ≥5 次，先测 run-to-run 波动，再谈跨平台差异 |
| 结论被误读为普遍规律 | 报告中明确限定算子、规模、精度、硬件与容差 |
